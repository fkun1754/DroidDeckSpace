# DroidDeckSpace 0.7.1

Fixes the runtime image boot failure introduced by the official runtime's deduplicated utilities.

## Fix

The official runtime ships most coreutils as `.l2s.*` symlink chains pointing at a single patched
uutils multi-call binary. That binary compares the requested utility name with `/proc/self/exe`;
under a plain DroidSpaces container the executable resolves to the shared payload name, so every
`ls`, `mkdir`, `cat`, `touch`, … fails with:

```
Security violation: Requested utility `mkdir` does not match executable name:
  /usr/lib/cargo/bin/coreutils/.l2s.env0001.0116
```

As a result a freshly installed runtime could not boot the container (`cannot create the guest
runtime directories`). 0.7.1 converts those chains to **hard links** after a runtime install, and
repairs an existing rootfs once at session preparation (`.droiddeck-l2s-hardlinks` marker), so
previously installed runtimes recover automatically.

## Install

1. Install DroidSpaces, grant it root and open it once.
2. Install `DroidDeckSpace-0.7.1.apk`.
3. Grant DroidDeckSpace root in KernelSU/Magisk.
4. Open the app → Setup → Overview → install the Linux runtime → press Play.

Upgrading from 0.7.0: the in-app stable update offers 0.7.1; after updating, the first session
repairs the existing runtime, no reinstall needed.
